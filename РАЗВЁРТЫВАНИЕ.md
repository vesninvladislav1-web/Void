## Один раз: адреса со ссылками

**Проверено 3 сентября 2026: на voidm.site это уже настроено.** Раздел
оставлен на случай переезда на другой сервер или новый домен.

Ссылки-приглашения (`/i/<код>`) и переписка без следа (`/t/<код>`) — это не
файлы на диске. Файла с таким именем нет, и nginx по умолчанию отвечает на них
`404 Not Found`. Человек, перешедший по ссылке, увидит страницу ошибки, а не
Void.

Лечится одной строкой в конфиге сайта. Открыть:

```
nano /etc/nginx/sites-available/voidm.site
```

Найти блок `location /` и привести его к такому виду:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

`try_files` читается так: «поищи файл с таким именем; не нашёл — поищи папку;
не нашёл и её — отдай index.html». Приложение само разберёт адрес и покажет
нужное. Блоки `/api` и `/signal` трогать не надо, они идут выше и проверяются
раньше.

Проверить и применить:

```
nginx -t && systemctl reload nginx
```

`nginx -t` разбирает конфиг, ничего не меняя. Пока он не сказал `syntax is ok`
и `test is successful`, перезагружать нельзя: с испорченным конфигом nginx не
поднимется, и сайт ляжет целиком.

Проверка, что получилось:

```
curl -s -o /dev/null -w "%{http_code}\n" https://voidm.site/t/00112233445566778899aabbccddeeff
```

Должно быть `200`. Если `404` — конфиг не применился.

## Папка для картинок (сторонний проект)

На той же машине можно раздавать файлы по ссылке — например, чтобы показать
фотографию тому, кому её некуда приложить. Это никак не связано с Void и
намеренно лежит **вне** его папки: иначе `git pull` спотыкался бы о чужие
файлы, а они попадали бы в репозиторий.

```
mkdir -p /var/www/foto
chown -R www-data:www-data /var/www/foto
```

В конфиг сайта, **выше** блока `location /`:

```nginx
location /f/ {
    alias /var/www/foto/;
    autoindex off;          # список файлов наружу не отдаём
    try_files $uri =404;    # нет файла — честная 404, а не страница Void
    expires 7d;
}
```

Порядок важен. Ниже стоит `try_files $uri $uri/ /index.html`, и без
отдельного блока запрос за несуществующей картинкой вернул бы страницу Void
с кодом 200 — выглядело бы так, будто файл есть, но «не открывается».

Проверить и применить:

```
nginx -t && systemctl reload nginx
```

Что важно понимать про эту папку:

- **Всё в ней доступно любому, у кого есть ссылка.** Пароля там нет и быть не
  может: тот, кто по ссылке ходит, никакого пароля не знает. Защита только
  одна — длинное случайное имя файла, которое не подобрать.
- Поэтому туда не кладут документы, переписку и вообще ничего, что жалко.
- К обещаниям Void это не относится: там сквозное шифрование, здесь обычная
  раздача файлов. Это разные вещи на одной машине.
- Диск общий с Void. Следи за размером:
  `du -sh /var/www/foto` и `df -h`.

Удалить всё, что старше месяца:

```
find /var/www/foto -type f -mtime +30 -delete
```

## Как отличить, кто ответил

Полезно помнить, потому что это экономит часы:

- **Void отвечает JSON** — `{"error":"..."}`;
- **nginx отвечает HTML** — страницей с заголовком вроде `413 Request Entity Too Large`.

Если в ответе HTML — до приложения запрос не дошёл, и чинить надо nginx.
